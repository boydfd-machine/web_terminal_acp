Enable Page Annotation Screenshots

Debug page annotation can attach a screenshot through the Electron desktop bridge or through the browser navigator.mediaDevices.getDisplayMedia() API. Browsers intentionally require user consent for this API, so Web Terminal ACP cannot silently enable screenshots for every browser.

Fast path: use the Electron desktop client, or open Web Terminal ACP from https://, http://localhost, or http://127.0.0.1 in a current desktop browser.

Mobile browsers and embedded webviews commonly do not expose display capture.

Supported Capture Paths

  • Electron desktop client: uses the app bridge and does not depend on browser getDisplayMedia().
  • Chrome, Edge, Firefox, or Safari desktop: uses getDisplayMedia() when the page is in a secure context and the browser or operating system allows screen capture.

Checklist

  1. Prefer Electron if you control the client environment.
  2. Use https:// for remote Web Terminal ACP URLs. For local development, http://localhost and http://127.0.0.1 count as trustworthy origins in modern browsers.
  3. If the app is embedded in an iframe, allow the browser display-capture permission for that frame.
  4. On macOS, grant Screen Recording permission to the browser or Electron app, then restart it.
  5. On managed Chrome or Edge, check enterprise policies that block or allow screen capture.
  6. On Linux Wayland, make sure the browser can use the desktop portal or PipeWire screen sharing path.

Browser And OS Settings

Chrome or Edge on HTTP intranet URLs

getDisplayMedia() is available only in secure contexts. If you must test an HTTP intranet origin, Chrome-based browsers can be started with an explicit testing override:

--unsafely-treat-insecure-origin-as-secure=http://host:port

Managed Chrome or Edge deployments can use the OverrideSecurityRestrictionsOnInsecureOrigin policy for the same kind of trusted internal origin exception.

Use this only for local or trusted development machines. The production fix is to serve Web Terminal ACP over HTTPS.

Iframe Embeds

If Web Terminal ACP is loaded inside another page, the parent page must allow display capture. Use a Permissions Policy that grants display-capture to the Web Terminal ACP origin, and include allow="display-capture" on the iframe.

Managed Chrome or Edge

Organization policy can disable screen capture entirely or restrict it by origin. Check policies such as ScreenCaptureAllowed and ScreenCaptureAllowedByOrigins with your browser administrator.

macOS

Open System Settings -> Privacy & Security -> Screen & System Audio Recording, enable the browser or Electron app, and restart it. A denied or stale macOS permission can make screenshots fail even when the browser API exists.

Linux Wayland

Browser screen capture normally depends on the desktop portal and PipeWire path. If the browser offers no screen or tab picker, update the browser, desktop portal packages, and PipeWire; then restart the browser session.

What Cannot Be Changed

  • The browser will still ask the user to choose what to share.
  • Web Terminal ACP cannot bypass operating-system privacy prompts.
  • Unsupported mobile browsers or webviews may never expose display capture.
